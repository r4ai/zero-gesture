## TCC and launch identity

Initially Zero Gesture was absent from both System Settings permission lists.
Direct executable startup recorded `Listen Event access is unavailable`,
published readiness, accepted the Settings UDS connection, and stayed alive in
pass-through mode. The user subsequently added the built `.app` to both
Accessibility and Input Monitoring using the normal System Settings UI and
reported both enabled. Their enabled switches were also observed through the
UI. No TCC database editing, reset, entitlement exception, or protection bypass
was performed.

Even after the UI grant, directly spawning `Contents/MacOS/zero-gesture` from
this terminal context still returned a denied Listen Event preflight. Starting
the same signed bundle through LaunchServices (`open -n -g -a ... --args
--engine`) started without that warning. Permission-dependent acceptance must
use the normal application launch path; direct-child process tests alone do
not establish the application's effective TCC identity.

For the isolated debug artifact, the tested launch command is:

```sh
open -n -g -a "$PWD/src-tauri/target/aarch64-apple-darwin/debug/bundle/macos/Zero Gesture.app" \
  --env ZG_P03_TEST_CONFIG_DIR=/tmp/zero-gesture-p06m-20260920/config \
  --env ZG_P03_TEST_NAMESPACE=p06m-20260920 \
  --env ZG_LOG_LEVEL=info --args --engine
```

The existing authenticated UDS `GetStatus`/`Shutdown` operations were exercised
by a temporary client outside the repository. The client reads the test

## Unresolved native termination gap

At 11:37:54 JST the running LaunchServices Engine (PID 624) received a Dock
`(aevt,quit)` AppleEvent. AppKit approved termination and exited by
11:37:54.952. No application worker-shutdown or executor/replay-drain log was
produced; its UDS subsequently refused connection. Restart through Settings
successfully reclaimed the stale endpoint.

Reproduction: launch the permission-granted Engine, choose Quit on its Dock
icon, then inspect the Engine log and its control endpoint. Compare with
authenticated UDS Shutdown, which emits the worker-stop sequence. The UI
operator's gesture observations at that time are still pending. **Loss of a
suppressed input was not observed**, but preservation during this termination
path has not been demonstrated and remains a serious acceptance risk.

Dependency inspection explains the missing gate: Tao 0.35.3 registers
`applicationWillTerminate:` and calls `AppState::exit()`. The Engine handles
Tauri `ExitRequested`, but its handler does not cover that native termination
path. This is not the tray's background shutdown path from ADR 0027. Fixing
only the final Exit notification by synchronously joining on the main thread
would risk waiting for the overlay's own main-thread drain. No such workaround
or delegate replacement was added. Until a focused native-termination fix and
physical suppressed-input test exist, use the tray Quit or authenticated UDS
Shutdown for controlled tests; do not mark shutdown acceptance complete.

Evidence: local `engine-624-unified.log`, `config/logs/engine-test.log`, and
`settings2-{open,preclose,closed}.txt` in the temporary evidence directory.
The private unified log is not committed or uploaded.
